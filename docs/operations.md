# Запуск, резервные копии и будущее размещение

`dev-server-pwa` сейчас разрешено только читать. Ни одна конфигурация из этого документа не применена к нему. Команды ниже для разработки выполняются на личном компьютере, с локальным Docker-контекстом.

## Локальные варианты

Основной вариант — Python и Node на компьютере, PostgreSQL/Redis/Mailpit в отдельном Compose-проекте `plyn-coffee`. Пошаговый запуск — в [README](../README.md).

Для проверки всего приложения в контейнерах:

```sh
docker --context desktop-linux compose -f compose.yaml -f compose.app.yaml build
docker --context desktop-linux compose -f compose.yaml -f compose.app.yaml up -d db redis mail
docker --context desktop-linux compose -f compose.yaml -f compose.app.yaml run --rm web python manage.py migrate
docker --context desktop-linux compose -f compose.yaml -f compose.app.yaml run --rm web python manage.py seed_demo
docker --context desktop-linux compose -f compose.yaml -f compose.app.yaml up -d web worker beat
```

На Linux с локальным Unix-сокетом вместо `desktop-linux` используйте свой проверенный локальный контекст, например `default`. Не подставляйте SSH-контекст сервера. Для свободного порта задайте `WEB_PORT` в локальном `.env`; `SITE_URL` для контейнера формируется из него.

Web, worker и beat используют один образ и отдельные от других проектов БД, Redis и media volume. Только один beat запускает расписание. Суммарные лимиты: PostgreSQL 1 ГБ, web/worker по 768 МБ, beat/Redis по 256 МБ, Mailpit 128 МБ. Лимиты — конфигурация, а не обещание производительности.

Проверка: `compose ps`, `/health/`, журналы конкретного сервиса. Фоновые события берутся из outbox в PostgreSQL; повторная доставка задачи не создаёт второй заказ, списание товара, ТТН или возврат. При недоступности Redis события остаются в БД. После восстановления брокера периодический обработчик подхватывает их.

Почта направляется только в локальный Mailpit. Отправка на внешний SMTP в demo-режиме запрещена настройками. Веб-интерфейс Mailpit опубликован только на loopback компьютера, в будущем размещении наружу не выводится.

## Резервная копия

Сохранять БД и пользовательские изображения согласованной парой; перед копированием остановить именно web/worker/beat магазина либо организовать окно без записи. PostgreSQL `pg_dump -Fc` даёт согласованный снимок БД. Статические изображения и исходники восстанавливаются из той же ревизии Git/образа.

Для локальной БД:

```sh
mkdir -p data/backups
docker --context desktop-linux compose exec -T db pg_dump -U plyn -d plyn -Fc > data/backups/database.dump
```

Для контейнерного media volume:

```sh
docker --context desktop-linux compose -f compose.yaml -f compose.app.yaml exec -T web tar -czf - -C /app/data media > data/backups/media.tar.gz
```

В режиме Python на компьютере media находится в `data/media`. Секреты и копии в Git не коммитятся; каталог `data/` игнорируется. Копии содержат контакты и токены, поэтому хранить их с ограниченными правами и шифрованием при переносе. Частота для будущего рабочего магазина определяется допустимой потерей данных; исходно планировать ежедневную копию и копию перед обновлением.

## Проверка восстановления

```sh
.venv/bin/python scripts/verify_restore.py
```

Скрипт принимает только локальный Docker-сокет. Создаёт backup основной локальной БД и media, добавляет временное синтетическое WebP для проверки изображения, восстанавливает в отдельную БД `plyn_restore_check_<случайный id>` и отдельный каталог. Сравнивает количества и детерминированные подписи всех строк каждой таблицы, а также SHA-256 всех файлов. Удаляет только свою временную БД и контрольный файл. Исходные таблицы не изменяются. Во время проверки не выполнять действия в демо.

Для образов с отдельным volume предварительно экспортировать media в собственный локальный каталог и передать `--media-root`. Отчёт без содержимого данных сохраняется в `docs/verification/restore-summary.json`; сами копии — в игнорируемом `data/backups`.

Реальное восстановление делать сначала в новое окружение: новый PostgreSQL volume, `pg_restore --no-owner --exit-on-error`, восстановление media с владельцем UID/GID 10001, затем `migrate --check`, проверка `/health/`, количества товаров и тестового заказа. Переключать трафик только после проверки. Не восстанавливать поверх работающей БД.

## Обновление и откат

1. Собрать неизменяемый образ с тегом ревизии; прогнать CI и совместимость миграций.
2. Сделать проверенную копию БД/media и сохранить предыдущий образ.
3. В согласованное окно остановить только процессы магазина, применить миграции, запустить web/worker/beat из одной ревизии.
4. Проверить health, витрину, checkout, обработку события и админку.
5. Для совместимых миграций вернуть предыдущий образ. Для несовместимых изменений восстановить пару БД/media в новое окружение и переключиться на него; слепой откат схемы не применять.

Эта последовательность документирована; обновление личного сервера не выполнялось.

## Подготовка подключения к существующему Traefik

Шаблон — [ops/compose.traefik.example.yaml](../ops/compose.traefik.example.yaml). Он добавляется к локальным Compose-файлам после отдельного разрешения на развёртывание. До этого только чтением определить имя сети Traefik, HTTPS entrypoint, certificate resolver и согласованный домен. Шаблон требует эти переменные и уникальный секрет, удаляет публикацию всех внутренних портов и подключает только web к входной сети.

На компьютере можно проверить синтаксис с вымышленными значениями:

```sh
SHOP_DOMAIN=coffee.example TRAEFIK_NETWORK=example_ingress TRAEFIK_ENTRYPOINT=websecure TRAEFIK_RESOLVER=example_tls SECRET_KEY=example-only-not-for-hosting docker --context desktop-linux compose -f compose.yaml -f compose.app.yaml -f ops/compose.traefik.example.yaml config --quiet
```

Проверка синтаксиса не создаёт сеть или контейнеры. Сеть, домен и resolver в примере не утверждают ничего о реальном сервере. Не создавать второй reverse proxy на 80/443. Не использовать БД, Redis и MinIO других приложений. До отдельного разрешения не копировать файлы, не менять DNS/Traefik, не создавать Docker-сети/volume и не выполнять миграции на `dev-server-pwa`.
